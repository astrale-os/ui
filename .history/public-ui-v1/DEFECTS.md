## Defect closure rules

- Close a defect only on the exact implementation revision carrying its mapped proof.
- A source build does not close package, registry-install, public-npm, visual, or live-release defects.
- A generated registry build does not close a real clean-consumer installation defect.
- A manually viewed screenshot does not close a visual matrix or accessibility defect.
- If a defect changes ownership, record the new owner and proof; do not delete the row.
- Legal and public-repository decisions remain maintainer gates even when all technical checks pass.
